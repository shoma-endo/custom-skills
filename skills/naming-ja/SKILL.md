# naming-ja — 比喩から考える日本語ネーミング

名前は「意味の説明」ではなく「圧縮された物語」。類語辞典で言い換えを探すのではなく、
「世の中でほかに同じ働きをしているものは何か」から考える。

[glacierphonk/naming](https://github.com/glacierphonk/naming)（MIT）の手順を、日本語の表記・読み・
商標・ドメイン事情に合わせて作り直したもの。原典のライセンスは `LICENSE.upstream`。

> 参照ファイルは手順ごとに必要なものだけ読む。最初に全部読まない。

## 手順

### 1. ブリーフ（候補を出す前に必ず固める）

会話や資料から分かる項目は埋め、分からない項目だけ聞く。

1. **何をするものか**（1文。機能の列挙ではなく本質）
2. **誰のためか**（業種・規模・年齢層。経営者か現場か）
3. **どう感じてほしいか**（親しみ／信頼／技術感／老舗感 など）
4. **既存のブランド・個人名と並べるか**（例:「〇〇｜山田太郎」）
5. **使いたくない言葉・方向性**
6. **確保したい場所**（ドメイン `.jp` / `.com`、X などの SNS、商標の区分）
7. **表記の希望**（ひらがな・カタカナ・漢字・英字）

ブリーフが曖昧なまま候補を出さない。

### 2. 比喩の領域を探す

[metaphor-mapping.md](metaphor-mapping.md) の6つの問いを、1文に縮めた機能に当てる。
有望な領域を2〜3個選ぶ。ブリーフで方向がはっきりしていれば、自分で選んで進める
（選んだ理由は手順7で示す）。

---

**手順3〜6は内部作業。** 生の候補一覧や途中経過は見せず、手順7で絞った最終候補だけを出す。

---

### 3. 候補を出す（内部）

領域ごとに30〜50個。不完全なものも混ぜる（傾向が見える）。
作り方: 実在の1語／2語の組み合わせ／語の変形・短縮／和語・漢語・外来語の言い換え／音から先に作る。
[principles.md](principles.md) の基準を最初に当てる。

### 4. 除外する（内部）

[anti-patterns.md](anti-patterns.md) の「危険信号チェックリスト」で2つ以上当てはまる候補を落とし、
10個前後に絞る。

### 5. 空き確認（内部・必須。飛ばさない）

道具で実際に確かめた結果だけを書く。記憶や推測で「空いている」と書かない。

1. **競合（最初にやる）** — WebSearch で `"候補名" <業種>`、`"候補名" サービス` を調べる。
   同じ領域に同名の事業があれば、その候補は落とす。
   WebSearch が使えないときは落とさず「競合: 未確認」と書く。空いていると断定しない。
2. **ドメイン** — `whois <名前>.jp` と `whois <名前>.com`。
   - `.jp` は `No match!!`、`.com` は `No match for domain` が出れば空き
   - `.co.jp` は法人しか取れない。個人事業なら `.jp` か `.com`
   - ローマ字表記が割れる名前（ou/o、chi/ti、ハイフン有無）は、表記ゆれ側も確認する
3. **商標** — J-PlatPat（https://www.j-platpat.inpit.go.jp/）の「商標検索」で、称呼（読み）で検索する。
   画面操作が必要なので、自動で取れなければ「商標: 本人が J-PlatPat で確認」と書いて渡す。
   よく関わる区分: 第35類（経営の助言・広告）、第41類（教育・研修）、第42類（ソフトウェアの設計・開発）。
   登録できるかの法的判断はしない（必要なら弁理士）。
4. **SNS** — X などのアカウント名は、ページが JavaScript で描画されるため HTTP 応答では判定できない。
   WebSearch で見るか、「SNS: 本人が確認」と書く。

判定:
- 同じ領域の競合あり・商標の明らかな衝突あり → 落とす
- ドメインの完全一致は取られているが、名前が強い → 表記ゆれ・接頭辞付きドメインを添えて残す
- 残りが3個未満 → 手順3に戻る。基準は下げない

### 6. 採点する（内部）

[evaluation.md](evaluation.md) の採点表で点を付け、文脈テストを通す。

### 7. 提示する（ここで初めて見せる）

最終候補を3〜5個。各候補に次を付ける。

- 名前（表記と読み。ドメイン用のローマ字表記も）
- 由来（15秒で話せる長さ）
- どの比喩か、なぜ効くか
- 点数
- 空き状況（**確認済み**と**未確認**を分けて書く）
- リスクと妥協点
- 名前に添える1行説明の方向（名前で説明しきらず、説明は1行説明に任せる）

採用は本人が決める。24時間置いてから決めるよう勧める。

## 戻るとき

- 候補が全部除外された → 手順2へ（領域を変える。同じ領域で数を増やさない）
- 空き確認で3個未満 → 手順3へ
- 70点を超える候補がない → 手順2へ
- 本人が全部却下した → 手順1へ（ブリーフを見直す）

## 守ること

1. ブリーフなしに候補を出さない
2. 類語の言い換えで作らない。比喩から作る
3. 手順3〜6の途中経過は見せない
4. 空き状況は道具で確かめた結果だけ。未確認は未確認と書く
5. 由来を説明できない名前は出さない
6. 最終候補は3〜5個に絞る
7. 本人が却下した方向は押し戻さない。別の領域を探す
